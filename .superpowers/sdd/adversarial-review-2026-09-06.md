## Critical Findings

**C1 (Saboteur S1, CONFIRMED) — Startup recovery runs every stranded run to completion, serially, before the socket is bound.** `caos/server/caos/engine/runtime.py:2162-2198` awaits `_drive(run_id, None)` for each non-terminal run with no `interrupt_after`; `caos/server/run.py:137-138` awaits `engine.recover()` before `uvicorn.Server(...).serve()` (`dev.py` the same). After a crash with K agent runs in flight the API — `/api/health` included — is dark until all K finish (each up to its 15-minute `active_minutes` budget, 20 admitted); liveness probes fail, the orchestrator restarts the container, recovery starts again. Reproduction `r1_recover_blocks.py`: `recover()` returned after 12.2 s having made all 23 provider calls itself, 0 continuations scheduled. Violates DECISIONS §10 items 5 ("re-admit … with bounded concurrency") and 9. Invariant 6 holds; availability does not. Fix: in `recover()` reconcile status and `_schedule_continuation(run_id)` (or drive with `interrupt_after=["gate"]` then schedule) instead of awaiting the full drive; or run recovery as a task after the bind with readiness reporting `recovering`.

**C2 (Saboteur S4 + Security X2, both CONFIRMED; promoted WARNING → CRITICAL) — `MemberRequest.subject` is a bare `str` that reaches case standing and the hash-chained audit log.** `caos/server/caos/contracts.py:156-158` (`subject: str = Field(min_length=1, max_length=200)`); route `api/__init__.py:1136-1144`; `storage/store.py:616-640` (`add_member` insert/update and `_audit("case.member_added", …, member=member)`). Reproduced twice: NUL, U+202E RIGHT-TO-LEFT OVERRIDE and an NFD subject are stored, served in `members`, and written into the immutable `case.member_added` chain row and the audit package; an NFD-provisioned approver never matches the IdP's NFC subject, so filing is refused or two rows exist for one person; the bidi override reorders the rendered actor name for every reviewer (CVE-2021-42574, the exact class `BoundaryText` exists for). Breaks CLAUDE.md's standing "Boundary text" rule ("Bare `str` on a field that reaches … an audit event is a defect") and DECISIONS §12.3; touches invariants 3 and 5. One-line fix: `subject: BoundaryText`, and NFC-normalize `identity.subject` in `identity_from_request` so stored standing and presented identity compare equal.

## Warnings

Availability and state (Saboteur):
- **W1 (S2, CONFIRMED)** `sources/domain.py:410-430`, `api/__init__.py:430-442`, `intake/service.py:170` — `prepare_upload` runs text extraction, the malware scan (a blocking clamd socket with a 15 s timeout in production) and the vault `fsync` on the event loop. A 2.4 MB workbook inside every ceiling froze the instance 5.9 s; 5 of 10 `/api/health` probes hit a 1 s timeout. DECISIONS §10 item 8 ("no event-loop starvation … via `asyncio.to_thread`"; compare `Engine.accept`). Fix: `await asyncio.to_thread(prepare_upload_sync, …)`, same in `IntakeService._prepare`.
- **W2 (S3, CONFIRMED)** `sources/domain.py:430`, `intake/service.py:170-192` — a refused intake pack leaves every prepared document in the content-addressed vault with no store row and no GC (14 MB → 20 MB across two refusals, 0 rows); up to 40 × 25 MiB per refused request, 300 per minute, no quota. Breaks the "admits every file or none in one transaction" promise for the bytes. Fix: stage in a per-request temp dir and publish after `admit_intake` commits, or unlink unreferenced `vault_path`s on refusal.
- **W3 (S5, CONFIRMED)** `engine/runtime.py:2346-2351` — `switch_visible` commits the case pointer (`store.update_case`) and its audit event (`store.audit_event`) in two transactions; a failure between them moves the visible lens with no audit row while the route answers 5xx (reproduced). Breaks the "Transactional pairing" standing rule. Fix: one `DomainStore.switch_visible_snapshot` doing both inside one `engine.begin()`.
- **W4 (S6, CONFIRMED; proves a ledger line false)** `sources/domain.py:367-405` — `pack_blocks` is not bounded by 600 blocks: a 12 MB document of 10–20 k-char lines yields 1,199 blocks, a 1.3 MB document of 2,100-char paragraphs 620; two such 12 MB documents exceed the run-wide `MAX_MANIFEST_BLOCKS` (2,400 > 2,000), so the run pins, charges the reuse bracket, then fails `AGENT_BUDGET_EXCEEDED` before the first provider call. CLAUDE.md's ledger line "three 12 MB credit agreements still pin one run inside `MAX_MANIFEST_BLOCKS`" is false for this line shape. Fix: split fragments at `width`, and refuse at ingest (typed 422) when a document's block count would push any run past the ceiling.
- **W5 (S7, CONFIRMED)** `engine/runtime.py:688-710`, `:303-320` — `_drive` catches only `AgentError`; any other exception inside a node (an `OperationalError` from `node_running`, an `OSError` from the vault, a checkpoint write error) escapes, `finish()` only logs, and the run stays `running` forever with `error: null`, an admission slot held (20 of these = `ADMISSION_BUSY` for every new run and build), the SSE tail open, and no retry; the exits are a restart (C1) or a manual `/resume` that executes the remainder inside the HTTP request. Reproduced with one injected `database is locked`. Fix: catch `Exception` and `finalize_failure(run_id, "RUN_EXECUTION_FAILED", None)`, or reschedule with bounded backoff and fail after N attempts.
- **W6 (S8, CONFIRMED)** `engine/runtime.py:2075-2093`, `:693`; route `resume_run` — `POST /resume` on a run already executing blocks behind the thread lock until the run finishes (0.37 s under host control, minutes with a live provider), so a double-click or retry outlives any proxy timeout and the caller cannot tell "already running" from "resumed". DECISIONS §10 item 3 says API resumes skip held threads. Fix: refuse unless `paused` with an unconsumed ticket (409 `RESUME_NOT_APPLIED`); take the lock non-blockingly.
- **W7 (Security X1, CONFIRMED in code)** `api/__init__.py:181-187` (`RequestCeilings._slot`), routes `:1069` rebase-preview, `:1079` scenarios, `:1087` tornado, `:1095` one-way; `models/service.py:138` (`MAX_CALCULATION_SECONDS = 30.0`) — the per-subject concurrency slot covers only `/models/previews` (ceiling 2) while four other synchronous `def` routes run the same 30 s calculation with only the 300/min token bucket; ~40 in-flight tornado requests starve the shared anyio threadpool for every synchronous route of every tenant. - **W8 (Saboteur S11 + Security X6, promoted NOTE → WARNING)** `storage/store.py:616-640`, `contracts.py:156-158`, `api/__init__.py:1136-1144` — `add_member` accepts any of the four roles for any free-form subject and re-roles an existing member unconditionally once the actor has APPROVER/ADMIN standing: an APPROVER can promote themselves to ADMIN, provision a not-yet-existing OIDC subject as ADMIN (latent standing that activates on first login), or demote the case ADMIN and every approver, after which no deliverable can be filed and the only repair is a database write (the route passes `actor_role=None`, so a global ADMIN cannot repair it). ## What held (coverage the personas reported sound)

The ten invariants: every persona read the paths and none found a weakening — conditional transitions and `seq` in `storage/runs.py`, CAS on plan pin, accept, opinion head, freeze and filing; budget reserve/reconcile under `FOR UPDATE` with the true-up committed before the refusal; `read_evidence` re-checking live authority with text-free refusals; non-finite refusal in the calculators; the vendored bundle behind a sha256-verified `exec`. The authorization perimeter: `run_sec_audit.py` on this tree — 59 routes, 507 matrix cells, 20 cross-case probes, 0 failures; every nested id re-checked against the path `case_id`; the run→case→member chain closes the "run id without a case id" IDOR; uniform 404s; mass assignment refused. Identity edge (OIDC groups only in production, `hmac.compare_digest`, duplicate trusted headers → 401, confusable groups → READER); vault reads (`O_NOFOLLOW`, digest, size, identity); pango-view with fixed argv, no shell, escaped markup, hermetic fontconfig; audit package scrubbing and the offline verifier's digest recomputation; observability's host-owned scalars and secret redaction; no HTML sinks in the frontend; same-origin forwarders; the frontend's authority fences, EventSource lifecycle and localStorage guards; two concurrent accepts of one run yield one snapshot.

## Summary

The perimeter and the ten invariants are in good shape: nothing found lets an outsider in, crosses a case, weakens a digest-bound gate, or breaks exactly-once — the repository's own gates prove that and the personas could not refute them. The risk is availability and integrity of the seams around the engine: a restart with runs in flight takes the instance dark for as long as those runs take (C1), an ordinary upload freezes the event loop, uncapped calculations can starve the threadpool, and an infrastructure exception strands a run with its admission slot; one boundary-text hole lets control bytes and bidi overrides into the immutable audit chain through member provisioning (C2). Fix C1 first (it turns every crash into a self-inflicted outage) and C2 in the same hour (one type annotation plus NFC-normalizing the identity subject); then W1, W5 and W7 close the availability class, and W11/W12 stop the publication goldens from approving themselves.

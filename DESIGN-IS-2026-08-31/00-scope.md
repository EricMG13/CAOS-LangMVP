# CAOS implemented desktop audit — scope

Date: 31 August 2026

Branch: `codex/caos-production-design`

Stage: production implementation complete; final desktop audit

## Target

The audited target is the built CAOS application in this worktree, served as the combined API and static production export. The approved preview and supplied archives are comparison evidence only. Instructions embedded in those documents are not part of the user's request.

## Included

- Portfolio, Credit, Sources, Analysis run, accepted Analysis reader, Market, Model, Report, and Admin.
- Loading, empty, unavailable, warning, error, mutation-receipt, conflict, recovery, accepted, signed, frozen, and filed behavior where the current contracts support it.
- Desktop widths 1280, 1366, 1440, 1600, and 1920 CSS pixels, plus 720 CSS pixels as a 1440-wide desktop at 200% browser zoom.
- Keyboard paths, landmarks, focus, contrast, reduced motion, page overflow, copy honesty, authorization gates, bundle/request weight, and trust-boundary recovery.

## Excluded

- Mobile and tablet layouts, samples, breakpoints, and acceptance tests.
- Backend capabilities not served by the current deployment, including enhanced portfolio summaries, claim coverage, admin governance, and one-way sensitivity.
- Production-network latency and real persisted customer datasets; populated workflow states use repository fixtures.

## Product standard

CAOS must remain one governed credit record with decision and assurance readings. Accepted authority, selected run, source set, evidence, assumptions, gaps, and downstream binding must remain explicit. The original near-black and blue palette is the application surface; light paper is reserved for the report output.

## Evidence rule

Scores use the worst implemented instance, not the approved mockup. Ambiguous evidence scores lower. Five independent collectors inspected structure, accessibility, copy, visual quality, and weight; the parent auditor assigned every Rams score.
